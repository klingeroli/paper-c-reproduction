# Paper C | Token & Cost Reproduction — Preliminary Check

**A small Python project exploring the token-distribution and pricing calculations in _Where the Tokens Go: A Quality-Cost Frontier for Controller-Driven Deep Research_ (Mehdi Bozzo-Rey, working draft, October 24, 2026).**

> **Scope:** This is a check of the arithmetic using *rounded figures printed in the paper*, **not yet a full reproduction using the original experiment transcripts**.

## 1. Project objective

The paper investigates whether a deep-research system can reduce its cost by using a less expensive model for research agents while keeping a stronger model for decision-making.

My first step was to understand and check the numbers reported in Sections 3–5:

- How many tokens are used by the **research agents** versus the **decision agents**?
- Why is the research share of **tokens** different from its share of **cost**?
- How much does the estimated cost change when the research agents use **Sonnet** rather than **Opus**?

## 2. What's in this repository?

| File | Purpose |
| --- | --- |
| `check_costs.py` | Calculates token shares and historical cost estimates from the paper's rounded token counts. |
| `README.md` | Explains the method, output and limitations. |

The script uses only standard Python; it makes **no API requests** and does **not** generate new AI research runs.

## 3. How `check_costs.py` works

**Step 1 — Enter the token data.** `TOKENS_M` stores four categories for each role, in **millions of tokens**, as shown in the paper:

| Token category | Meaning |
| --- | --- |
| Input | New tokens sent to a model |
| Output | Tokens generated by the model |
| Cache creation | Input content written into the prompt cache |
| Cache read | Previously cached content read again |

**Step 2 — Add up token usage.** `token_total_m()` sums the four categories for each role. The script calculates research and decision percentages from their combined total.

**Step 3 — Apply the historical pricing rules.** `price_usd()` multiplies each token category by the paper's model-specific rates, using **1.25× the input price for cache creation** and **0.10× the input price for cache reads**. Because the counts are already in millions, the rates are expressed in dollars per million tokens.

**Step 4 — Compare configurations.** The script calculates:

- **All-Opus counterfactual:** what the *same measured token quantities* would cost if priced entirely at Opus rates.
- **Tiered introductory:** Opus for decision agents, Sonnet introductory rates for research agents.
- **Tiered standard:** Opus for decision agents, Sonnet standard rates for research agents.

Finally, it computes the percent saving relative to the all-Opus counterfactual.

## 4. Run the calculation

With Python 3 installed, open a terminal in this folder and run:

```bash
python3 check_costs.py
```

No API key, paid service or extra Python package is required.

## 5. Results

The script should produce results close to the following reported values:

| Metric | Paper | Script (approximate) |
| --- | ---: | ---: |
| Research token share | 83.8% | 83.75% |
| Decision token share | 16.2% | 16.25% |
| Research share of all-Opus-priced cost | 66.4% | 66.44% |
| All-Opus counterfactual | $201.67 | $201.68 |
| Tiered cost — introductory | $121.32 | $121.29 |
| Tiered cost — standard | $148.10 | $148.08 |
| Introductory saving | ~40% | ~39.9% |
| Standard saving | ~27% | ~26.6% |

**Why don't all the cents match?** The PDF rounds token counts before displaying them. The script uses those rounded counts, while the original cost results were calculated using more precise records. The small differences do not, by themselves, indicate an error.

## 6. What this does *not* reproduce yet

This is a **preliminary verification of published table arithmetic**. It does not:

- Read the original experiment transcripts or extract API usage records.
- Remove duplicate streaming usage updates.
- Verify the paper's original model tagging or run inclusion rules.
- Recreate the reported token counts directly from raw artifacts.
- Measure a separate all-Opus run's bill.

The paper notes that the token totals also include smoke-test activity and reruns. The pricing results are specific to that measured volume and the **historical rates quoted in the draft**, not current API prices.
